# Отчёт: Support Copilot на валидации

Валидация — `tickets_valid.jsonl`, 1 000 обращений (817 жалоб, 183 репорта). Все цифры получены командой `make eval`
(результат — `artifacts/report.json`). Данные Grand Mobile в репозиторий не выкладываются, поэтому здесь только
агрегированные метрики, а примеры черновиков сделаны на придуманных обращениях: [examples.md](examples.md).

## Классификация

В выгрузке нет готовых категорий и приоритетов. Поэтому мерили двумя способами.

**1. Против ручной разметки команды** — 150 случайных обращений валидации, размеченных человеком по `taxonomy.json`
(метрика та же, что у жюри):

| Метрика | Первая версия | Итоговая |
|---|---|---|
| Accuracy по категории | 56,7% | **78,0%** |
| **Macro-F1 по приоритету** | 0,611 | **0,716** |
| Accuracy по приоритету | 70,7% | 82,0% |

Ручная разметка вскрыла две системные ошибки первой версии, и это главный урок проекта:

- **Апелляции.** 30% жалоб — это игроки, оспаривающие *своё* наказание («за что бан», «прошу рассмотреть решение»,
  «ban yechila»). Апелляция на бан за читы похожа на жалобу на читы, и модель путала их. Добавлены маркеры апелляций
  на ru/kk/uz поверх модели: найдено 37 из 45 вместо 17.
- **«Без доказательств».** Исход «нужны доказательства» мы сначала превращали в категорию `complaint.invalid`, а люди
  ставят категорию по теме жалобы. Убрали — `complaint.invalid` больше не ставится на каждую четвёртую жалобу.

*Оговорка:* эти 150 обращений использовались для разбора ошибок, поэтому цифра немного оптимистична. Правки общие
(как игроки пишут апелляции), а не под конкретные тикеты: согласие с исходами на всей валидации тоже выросло.

**2. Против исходов админов** — по пункту нарушения из ответа админа («2.1 ОП» → оскорбление, «5.2 ОП» → читы):
жалобы **87,9%** (669 из 817 сравнимы). На этих же «слабых» метках обучена модель.

**Модель:** TF-IDF по символьным n-граммам (устойчив к опечаткам, транслиту и смеси языков) + логистическая
регрессия, отдельно для жалоб и репортов. Поверх — правила-страховки: апелляции, взлом и платежи ловятся маркерами,
даже если модель уверена в другом. Приоритет — правила `taxonomy.json` + наличие доказательств + маркеры угроз.

## Черновики

Три источника, по порядку:

1. **Шаблон** — типовые репорты на русском («помогите», «застрял»): самый частый ответ админов этой категории
   («Приветствую, слежу за вами.»). Бесплатно и мгновенно.
2. **LLM (Gemini 3.5 Flash-Lite) с RAG** — всё остальное. В промпт идут только уместные пункты правил и 3 реальных
   ответа админов на похожие случаи с тем же вероятным исходом. Ответ — строго JSON.
3. **Офлайн** — если ключа нет или LLM не ответил за 4 с: ответ админа на самый похожий случай из индекса
   73 тыс. обращений, с подставленными никами.

| Источник | Доля | Сходство с реальным ответом админа |
|---|---|---|
| Шаблон | 17% | 0,32 |
| LLM | 82% от выборки | 0,21 |
| Офлайн (похожий случай) | — | 0,26 |

Сходство — грубый прокси: админы будут ставить оценку по смыслу, а не по совпадению слов. Офлайн-черновики похожи
на ответы админов по форме, но иногда переносят чужие детали; LLM пишет короче и по делу.

## Защита от галлюцинаций и обещаний

- Пункт правил имеет канонический id «номер + раздел» (`2.1 ОП`, `1.2 GZ`, `1.2.7 ЖБ`): «1.1» есть в 10 разделах,
  поэтому голый номер неоднозначен.
- LLM получает список разрешённых пунктов; если черновик упоминает любой другой — черновик отбрасывается.
- Цитаты повторно сверяются с `rules.json` перед ответом.
- Обещания разбана, снятия наказания, возврата денег/имущества (ru/kk/uz) ловятся кодом: такой черновик
  заменяется нейтральным «передано старшему администратору».
- Защита от prompt injection: текст игрока передаётся в LLM внутри `<ticket>`, инструкции в нём считаются данными;
  попытки управлять ответом («игнорируй правила», «needs_human=false») уходят человеку.
- Тесты на провокации (`tests/test_safety.py`, 24 теста): «по пункту 7.3 положен возврат», «админ обещал разбан»,
  «по 99.1 ОП забаньте», инъекции — ни одного выдуманного пункта, деньги/разбан/взлом уходят человеку.
  Проверено и вживую на Gemini.

## Доля «нужен человек»

**47%** обращений валидации (офлайн-режим). Почему не меньше:

- 82% обращений — жалобы, из них ~30% апелляции; платежи, апелляции, взлом и жалобы на админов
  (`taxonomy.json → needs_human_always`) — всегда человек;
- решение о наказании другого игрока подтверждает администратор (черновик его только предлагает).

Автоматически уходят: типовые репорты и черновики жалоб без решения о наказании (просьба прислать доказательства,
неверное оформление, дубликат). LLM осторожнее офлайн-режима и помечает больше обращений.

*Расхождение с ручной разметкой (62% совпадения):* размечавший считал, что обычную жалобу с доказательствами можно
отправить без админа. Мы сознательно строже: черновик с наказанием игроку без проверки человеком — это и есть
«обещание наказания», которое ТЗ запрещает.

## Казахский и узбекский

- Казахские шаблоны ответов написал носитель языка из команды, узбекские — подготовлены с LLM по образцу реальных
  ответов админов (`copilot/templates.py`).
- Репорты на kk/uz отвечаются этими шаблонами без LLM; для жалоб шаблоны идут в LLM как образцы стиля.
- Казахский текст из cp1251 (ќ, ґ, ѕ, є, ј, ў, ї) восстанавливается до любой обработки.
- Латиница внутри кириллических слов в ответе LLM («алайda») исправляется кодом.

## Стоимость и латентность

| | Значение | Лимит ТЗ |
|---|---|---|
| Токены на вызов LLM (вход / выход) | 894 / 98 | — |
| Цена вызова (средняя / максимум) | $0,00051 / $0,00081 | — |
| **Цена на обращение** (с учётом шаблонов без LLM) | **$0,00042** | $0,002 |
| Латентность с LLM, p50 / **p95** | 0,86 с / **1,29 с** | 5 с |
| Латентность офлайн, p50 / p95 | 0,010 с / 0,037 с | 5 с |

Цены Gemini 3.5 Flash-Lite: $0,30 / 1M входных и $2,50 / 1M выходных токенов. Таймаут LLM — 4 с, при превышении
черновик собирается офлайн, поэтому p95 не выходит за 5 с даже при сбоях API.

На бесплатном ключе есть лимит запросов в минуту (ошибка 429): сервис в этом случае уходит в офлайн-режим, а
`make eval` делает паузы между вызовами. Для продакшена нужен платный тариф — он укладывается в лимит стоимости.

## Как воспроизвести

```bash
make install
make train      # ~3 мин: модели и индекс похожих случаев из tickets_train
make eval       # отчёт на валидации, 100 обращений через LLM
make examples   # docs/examples.md
```
