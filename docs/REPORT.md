# Отчёт: Support Copilot на валидации

Валидация — `tickets_valid.jsonl`, 1 000 обращений (817 жалоб, 183 репорта). Все цифры получены командой `make eval`
(результат — `artifacts/report.json`). Данные Grand Mobile в репозиторий не выкладываются, поэтому здесь только
агрегированные метрики, а примеры черновиков сделаны на придуманных обращениях: [examples.md](examples.md).

## Сводка против критериев ТЗ

| Критерий ТЗ | Вес | Что получилось | Как мерили |
|---|---|---|---|
| Классификация | 25% | категория жалоб совпадает с исходом у админа в **83,1%** | см. «Классификация» — честные оговорки ниже |
| Качество черновиков | 30% | черновики в стиле админов, сходство с реальным ответом 0,21–0,32 | прокси: близость к ответу админа по символьным n-граммам |
| Без галлюцинаций | 20% | **0 выдуманных цитат из 182**, 0 упоминаний несуществующих пунктов | каждая цитата сверяется с `rules.json` |
| Казахский и узбекский | 15% | **100%** черновиков LLM на языке игрока (132 kk/uz обращения) | язык черновика = язык обращения |
| Стоимость и латентность | 10% | **$0,00042** за обращение, **p95 = 1,29 с** | 100 обращений через Gemini 3.5 Flash-Lite |

## Классификация

**Важная оговорка.** В выгрузке нет готовых категорий и приоритетов. Мы восстановили категорию жалобы по исходу,
который записал админ: пункт нарушения («2.1 ОП» → оскорбление, «5.2 ОП» → читы), апелляция, «неверно оформлена».
На этих метках обучена модель и с ними же сравнивается предсказание. Это **согласие с исходом**, а не точность
против ручной разметки жюри.

| Вид | Сравнимо с исходом | Совпадение |
|---|---|---|
| Жалобы | 669 из 817 | **83,1%** |
| Репорты | 84 из 183 | 100%* |

\* Метки репортов построены на ключевых словах, и модель их воспроизводит, поэтому 100% не говорит о реальной точности.
Для честной оценки команда вручную размечает 150 случайных обращений валидации (`data/gold/label_me.xlsx`);
когда разметка заполнена, `make eval` сам считает accuracy по категории и macro-F1 по приоритету против неё.

**Где модель ошибается (жалобы):** чаще всего путает апелляции и DM с «без доказательств» (`complaint.invalid`),
22 и 14 случаев. Это ожидаемо: исход «нужны доказательства» зависит от скриншотов, которых в данных нет.

**Модель:** TF-IDF по символьным n-граммам (устойчив к опечаткам, транслиту и смеси языков) + логистическая
регрессия, отдельно для жалоб и репортов. Поверх — правила-страховки: взлом и платежи ловятся ключевыми словами,
даже если модель уверена в другом. Приоритет — правила `taxonomy.json` + наличие доказательств + маркеры угроз.

## Черновики

Три источника, по порядку:

1. **Шаблон** — типовые репорты на русском («помогите», «застрял»): самый частый ответ админов этой категории
   («Приветствую, слежу за вами.»). Бесплатно и мгновенно.
2. **LLM (Gemini 3.5 Flash-Lite) с RAG** — всё остальное. В промпт идут только уместные пункты правил и 3 реальных
   ответа админов на похожие случаи с тем же вероятным исходом. Ответ — строго JSON.
3. **Офлайн** — если ключа нет или LLM не ответил за 4 с: ответ админа на самый похожий случай из индекса
   73 тыс. обращений, с подставленными никами.

| Источник | Доля | Сходство с реальным ответом админа |
|---|---|---|
| Шаблон | 17% | 0,32 |
| LLM | 82% от выборки | 0,21 |
| Офлайн (похожий случай) | — | 0,26 |

Сходство — грубый прокси: админы будут ставить оценку по смыслу, а не по совпадению слов. Офлайн-черновики похожи
на ответы админов по форме, но иногда переносят чужие детали; LLM пишет короче и по делу.

## Защита от галлюцинаций и обещаний

- Пункт правил имеет канонический id «номер + раздел» (`2.1 ОП`, `1.2 GZ`, `1.2.7 ЖБ`): «1.1» есть в 10 разделах,
  поэтому голый номер неоднозначен.
- LLM получает список разрешённых пунктов; если черновик упоминает любой другой — черновик отбрасывается.
- Цитаты повторно сверяются с `rules.json` перед ответом.
- Обещания разбана, снятия наказания, возврата денег/имущества (ru/kk/uz) ловятся кодом: такой черновик
  заменяется нейтральным «передано старшему администратору».
- Тесты на провокации (`tests/test_safety.py`): «по пункту 7.3 положен возврат», «админ обещал разбан»,
  «по 99.1 ОП забаньте» — ни одного выдуманного пункта, деньги/разбан/взлом уходят человеку.

## Доля «нужен человек»

**42%** обращений валидации (офлайн-режим). Почему не меньше:

- 82% обращений — жалобы на игроков, а решение о наказании по ТЗ подтверждает администратор;
- платежи, апелляции банов, взлом и жалобы на админов (`taxonomy.json → needs_human_always`) — всегда человек.

Автоматически уходят: типовые репорты и черновики жалоб без решения о наказании (просьба прислать доказательства,
неверное оформление, дубликат). LLM осторожнее офлайн-режима и помечает больше обращений.

## Стоимость и латентность

| | Значение | Лимит ТЗ |
|---|---|---|
| Токены на вызов LLM (вход / выход) | 894 / 98 | — |
| Цена вызова (средняя / максимум) | $0,00051 / $0,00081 | — |
| **Цена на обращение** (с учётом шаблонов без LLM) | **$0,00042** | $0,002 |
| Латентность с LLM, p50 / **p95** | 0,86 с / **1,29 с** | 5 с |
| Латентность офлайн, p50 / p95 | 0,010 с / 0,037 с | 5 с |

Цены Gemini 3.5 Flash-Lite: $0,30 / 1M входных и $2,50 / 1M выходных токенов. Таймаут LLM — 4 с, при превышении
черновик собирается офлайн, поэтому p95 не выходит за 5 с даже при сбоях API.

На бесплатном ключе есть лимит запросов в минуту (ошибка 429): сервис в этом случае уходит в офлайн-режим, а
`make eval` делает паузы между вызовами. Для продакшена нужен платный тариф — он укладывается в лимит стоимости.

## Как воспроизвести

```bash
make install
make train      # ~3 мин: модели и индекс похожих случаев из tickets_train
make eval       # отчёт на валидации, 100 обращений через LLM
make examples   # docs/examples.md
```
